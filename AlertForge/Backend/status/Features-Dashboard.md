## 1. Overview / Dashboard

The landing page after login — gives a fast read of all active and recent incidents.

- **Incident list table** — all incidents displayed with title, affected service, severity, status, started-at timestamp, and duration
- **Inline severity editor** — click the severity badge on any row to change it (P1 / P2 / P3) via a dropdown, no page reload
- **Inline status editor** — click the status badge on any row to update it (Active / Monitoring / Investigating / Identified / Resolved) inline
- **Tab filters** — filter rows by All / Active / Monitoring / Resolved in one click
- **Create Incident sheet** — slide-in panel from the right with fields for incident name, service/team, severity, status, started-at, and duration
- **Row navigation** — click any incident row to go directly to its detail page
- **Breadcrumb navigation** — always visible in the top header showing your current location

---

## 2. Incidents

A full card-based view of all incidents with richer context per incident.

- **Incident cards** — each card shows title, service URL, severity badge, status badge, started-at, duration, responder avatars, and the latest timeline update with a timestamp
- **Active pulsing indicator** — live red dot on cards for any non-resolved incident
- **Color-coded left border** — card border color reflects incident status at a glance (red = active, orange = monitoring, blue = investigating, etc.)
- **Tab filters with counts** — All / Active (with count badge) / Monitoring (with count badge) / Resolved
- **Search** — filter cards by incident title or service name in real time
- **Create Incident sheet** — slide-in form with title, service, severity, status, started-at, and duration fields
- **View Incident Details button** — navigates to the full incident detail page

---

## 3. Incident Detail

The full single-incident view with live timeline, AI analysis, and status management.

**Header & Meta**
- Live pulsing red dot for active incidents
- Incident title, severity badge, and inline status dropdown
- Meta row — service URL, started-at, live elapsed timer (orange, ticking in real time), detection source (UptimeRobot / Manual), and resolved-at timestamp when applicable

**Timeline (left column — 60%)**
- Chronological feed of all events — system-generated events (italic, grey) and manual updates (author avatar + name)
- Public / Internal tag on every event — green eye for public, lock icon for internal
- Auto-scrolls to the latest event
- **Update composer** — textarea to post a new timeline update
- **Public / Internal toggle** — switch the visibility of your update before posting
- **Post Update button** — adds the update to the live timeline instantly

**Info Panel (right column — 40%)**
- **Details card** — Incident ID, source, affected URL, severity
- **Responders card** — avatar, name, and role (Lead / Support) for every responder
- **Affected Services card** — each service with a live status dot (down / degraded / operational)
- **AI Root Cause card** — numbered list of probable causes generated by Claude; shows an "Analyse →" button if not yet generated, "Regenerate" if already done; loading state with pulse animation
- **Postmortem card** — shows "Available after resolved" for active incidents, "Generate with AI" button for resolved ones, and a "View →" link if already generated

**Action Bar**
- **Open War Room button** — visible only on active incidents, navigates to the War Room
- **View Postmortem button** — visible only on resolved incidents

## 4. War Room

A real-time command centre for responding to an active incident.

**Command Bar (top)**
- Back button to the incident detail
- Incident title + severity badge
- **Status Stepper** — pill-style progress bar (Investigating → Identified → Monitoring → Resolved); click any step to advance
- Notification bell with a badge showing total unread activity count
- **Resolve Incident button** — opens a confirmation modal

**Timer Bar**
- Service name
- Large monospace live timer (hours : minutes : seconds) in severity color — freezes on resolve
- Live / Resolved badge with pulsing dot
- **Generate Postmortem button** — unlocks after incident is resolved, locked with "Resolve to unlock" label while active

**Left Panel — Presence & Quick Actions (20%)**
- **In This Room** — responder avatars with online/offline indicator dots
- **Quick Actions** — 4 shortcut buttons: Add Note, Add Task, Add File, Share Link — each switches the active tab and focuses the composer
- **AI Root Cause** — numbered list of Claude-generated probable causes

**Centre Panel — Tabbed Workspace (50%)**

Four tabs, each with its own feed and badge counter for new activity:

- **Updates tab** — live feed of system and manual updates; each entry shows author avatar, name, timestamp, and a Public / Internal tag; composer with Public / Private toggle and Post button (Enter to submit)
- **Tasks tab** — checklist of action items with assignee and timestamp; check/uncheck to mark done; done items get strikethrough + fade; inline "Add task" input (Enter to add, Escape to cancel); dashed "Add task" button at the bottom
- **Notes tab** — monospace note cards per author with timestamp; post via the composer
- **Files tab** — file and link entries with icon, filename/URL, author and time; paste a filename or URL to add

**Right Panel — AI Investigation Checklist (30%, desktop only)**
- AI-suggested investigation steps with checkboxes — check off as you go
- **Similar Past Incidents** — 2 most relevant past incidents with title, date, and how long they took to resolve

**Resolve Modal**
- Confirmation dialog explaining what resolving does (notifies responders, updates status page, triggers postmortem)
- Cancel / Yes, Resolve buttons

**Toast Notifications**
- Non-blocking toasts in the bottom-right for every action (update posted, task added, status changed, incident resolved) — auto-dismiss after 3.5 seconds with manual dismiss

## 5. Postmortem

A structured AI-drafted document for post-incident review — fully editable.

**Header**
- Incident title, severity badge, and postmortem status badge (Draft / In Review / Published)
- **Status stepper** — Draft → In Review → Published with step indicators
- Meta row — service, started-at, resolved-at, total duration, lead responder
- **Export button** — download the postmortem
- **Move to [Next Status] button** — advances the workflow (orange for In Review, green for Published)

**AI Generate Bar**
- Prominent violet-accented banner at the top of the document
- **Generate button** — sends the incident timeline to Claude and drafts all sections automatically
- **Regenerate button** — re-runs the AI generation after editing
- Loading state with pulse animation during generation

**Document Sections (left column — 65%)** — all collapsible, all editable

- **Summary** — editable paragraph; click to edit, Save / Cancel inline
- **Root Cause Analysis** — numbered bullet list; hover any item to reveal a remove button; Add item input at the bottom
- **Impact** — editable paragraph describing affected users, duration, and data loss status
- **What Went Well** — bullet list with green check icons; add / remove items inline
- **What Went Wrong** — bullet list with red X icons; add / remove items inline
- **Action Items** — checklist with progress bar (done/total); each item has assignee, check-off button, and remove; inline add form with task description + optional assignee field; dashed "Add action item" button

**Sidebar (right column — 35%)**
- **Incident Details card** — ID, service, severity, started, resolved, duration
- **Responders card** — avatars with Lead Responder label
- **Incident Timeline** — read-only scrollable timeline with Public / Internal tags (same format as Incident Detail)
- **Action Items Summary** — 3 stat boxes: Total / Open / Done

## 6. Services

The team's service registry — every service being monitored lives here.

**Stats Row**
- 4 cards: Total Services, Operational (green), Degraded (orange), Outage (red) — live counts

**UptimeRobot Nudge Banner**
- Appears if UptimeRobot is not yet connected — links directly to the Integrations page
- Dismissable

**Filter Tabs**
- All / Operational / Degraded / Outage — with live counts per status

**Search**
- Real-time filter by service name or URL

**Service Cards (2-column grid)**
- Service name, URL with external link
- **Status badge** — Operational / Degraded / Outage with icon
- **Monitor type badge** — UptimeRobot (orange) / SDK (violet) / Manual (grey)
- Incident count and uptime % at the bottom
- Created-at date
- **`...` action menu** — View Incidents, Set Status (change to Operational / Degraded / Outage), Delete Service

**Add Service Sheet**
- Slide-in panel with service name, URL, and a monitoring type selector
- Monitoring type shown as selectable cards (UptimeRobot / SDK / Manual) each with a description of how that method works

## 7. Integrations & API Keys

Three sections for connecting AlertForge to external tools and your own backend.

**UptimeRobot Webhook**
- Auto-generated unique webhook URL per team — displayed in a copy field
- **Copy button** — one-click copy to clipboard with a ✓ confirmation
- **Send Test Payload button** — fires a test POST to your webhook and confirms receipt
- Step-by-step setup guide (5 steps) for configuring UptimeRobot
- Link to open UptimeRobot dashboard

**SDK Integration**
- Short description of what the SDK does
- **Tabbed code blocks** — 5 tabs: Install / Initialize / Report Incident / Resolve / Post Update
- Each tab shows a syntax-highlighted code snippet (via `react-syntax-highlighter`) in a dark theme matching the UI
- Language label (bash / javascript) in the code block header
- **Copy button** per code block
- Security warning reminding developers to use environment variables, not hardcoded keys

**API Keys**
- Table of all generated keys — label, obfuscated preview, created date, last used
- **Generate New Key** — inline input for a key label; generates the key on submit
- **Show-once reveal** — the full key is shown in a highlighted green box immediately after creation with a copy button and a "won't show again" warning; dismissed when the user confirms they've copied it
- **Revoke button** — removes the key from the table with a hover-red destructive style

## 8. Status Page

A public-facing status dashboard — shown within the dashboard for team preview.

**Overall Status Banner**
- Full-width banner that dynamically shows:
  - 🟢 **All Systems Operational** — all services healthy, no active incidents
  - 🟠 **Degraded Performance** — one or more services degraded
  - 🔴 **Service Disruption** — active incidents or outages detected
- Pulsing dot reflects current severity

**Stats Row**
- 4 cards: 30-day avg uptime %, Services Online (X/total), Active Incidents (red if > 0), Incidents This Month

**Services Grid (2-column)**
- Each service card shows name, URL, current status dot + label, response time
- **90-day uptime bar graph** — 90 bars, one per day; bar height varies by status (operational = short, degraded = medium, outage = tall); hover any bar for a tooltip showing the date and status
- Uptime % displayed bottom-right of each card

**Active Incidents**
- Section only renders when there are live incidents
- Each incident shows title, service, severity + status badges, started-at, live duration
- Full public update timeline with timestamps — same visual style as the incident timeline

**Incident History**
- Accordion list of all resolved incidents from the past 30 days
- Click any row to expand — shows resolved-at, total duration, and all public timeline updates
- Empty state with green checkmark if no incidents in the period

## 9. Team

Member management, invitations, and role permissions.

**Stats Row**
- 4 cards: Total Members (with online count), Admins (violet), Responders (blue), Viewers (grey)

**Members Table**
- Columns: Member (avatar + name + email + online dot), Role, Status, Incidents Responded, Actions
- **Online indicator** — green dot for online, grey for offline on each avatar
- **"You" badge** — your own row is marked, with no action menu (can't remove yourself)
- **`...` action menu** per member:
  - Change Role — radio group to switch between Admin / Responder / Viewer inline
  - Remove from Team — destructive option in red

**Pending Invites**
- Section only renders when there are outstanding invites
- Shows email, role, sent date, and expiry
- **Resend button** — flips to a green "Sent ✓" for 2 seconds then resets
- **Revoke button** — removes the invite immediately
- Badge showing total pending count

**Invite Member Sheet**
- Slide-in panel with email input
- **Role selector** — 3 selectable cards (Admin / Responder / Viewer) each with a description so the inviter understands what they're assigning
- Send Invite button

**Role Permissions Legend**
- 3 cards at the bottom — one per role
- Each card shows the role badge, a description, and a checklist of exactly what that role can do

## Global Layout Features

- **Collapsible sidebar** — click the rail on the right edge to collapse to icon-only mode; tooltips appear on hover when collapsed
- **Breadcrumb navigation** — always visible in the sticky header, links back to parent pages
- **Sidebar trigger** — hamburger button in the header to toggle the sidebar on any screen size
- **Dark theme** — pure black (`#000`) background with zinc-based card surfaces throughout
- **Clerk authentication** — all dashboard routes are protected; unauthenticated users are redirected to login
- **User footer** — bottom of the sidebar shows avatar, name, and email with a dropdown for sign out
